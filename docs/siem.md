# Internal SIEM

Security Information and Event Management combines ingestion, normalization, storage, search, detection, correlation and investigation. BankGuard implements this directly over PostgreSQL/SQLite; no OpenSearch service is required.

Normalized events expose `event_id`, UTC `timestamp`, `event_type`, `severity`, UUID `user_id`/`account_id`, `source_ip`, optional `device_id`, fictional `location`, structured `metadata`, `source` and optional `run_id`. Human-readable customer IDs remain on User and can be searched as `BG1001`.

The event explorer uses ORM predicates for text, type, severity, customer, IP and time filters. Queries are paginated, capped at 100 items and ordered by timestamp with an ID tie-breaker. Indexes cover user/time, type, severity, IP and run. Raw structured event details are visible in an accessible dialog. Hunt presets use the same endpoint; suspicious-password-change hunting uses matched alert relationships.

Alerts store their source event, rule, reason, severity and optional incident link. A correlated incident captures all matching events through `IncidentEvent` and immutable-at-capture evidence snapshots. Evidence hashes are computed over canonical sorted JSON. The event stream itself is durable; SSE is a notification mechanism for fresh commits, not a separate source of truth.

On connection/reconnect, SSE sends a current recent-event snapshot. React then reloads relevant queries. No dashboard metric is generated by a frontend random-number function or static array. Chart statistics come from SQL count/sum/group operations and bounded recent risk evaluations.

The local dataset is suitable for a teaching lab. Full-text indexing, retention policies, partitioning, ingestion backpressure and distributed streaming are future scale considerations.
